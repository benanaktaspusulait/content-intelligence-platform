ARCHITECTURE AND SCOPE
The accepted creative Prompt V2, schema, validators, scoring, weights, thresholds, taxonomy, historical evidence and production selection are unchanged. Three additive files provide a bounded transport/replay wrapper, CLI and mock tests. No new quality judge is introduced.
The original single40 request failed with APITimeoutError and0 usable response bytes; this is an execution failure, not a creative quality result. It remains immutable at semantic-live-v2-count-40-run-001. Recovery uses a separate repository-safe identity semantic-live-v2-count-40-run-001-recovery-001, linked to that parent.

TWO REQUESTS, NOT RETRIES
Both A and B requests are fully prepared before A starts. Each receives the complete exact accepted V2 system instructions and20-item request envelope. B receives no content from A. A failing does not cancel B; B is an independently authorized planned request. A successful partial yield is retained. No replacement, third request, retry loop, model change or generate-until-valid path exists. The exclusive recovery directory prevents reexecution into the same experiment.
Provider/model:DeepSeek/deepseek-v4-pro. Output ceiling32768 tokens per shard. SDK max_retries=0 is checked before complete(). Read timeout120s, connect15s, write60s, pool15s. A separate spawned worker provides a300s parent-enforced wall deadline, then termination/kill without restart. These are local experiment limits; no application timeout is changed. The accepted generation configuration's legacy90s field is not used for this transport; exact actual transport limits are stored separately.
Only request batch metadata changes:20 requested raw items, shard identity/ID prefix, output-token and transport bounds. The creative system text and candidate item schema are identical to accepted V2. No V2.1 is created.

SOURCE AND COMBINED PIPELINE
Each shard preserves its exact transmitted request, exact raw response, request-start marker, completion/failure metadata, usage and optional provider-reported cost. Missing usage/cost remains unknown; no cost is estimated. Shard response strings are never concatenated or rewritten.
A deterministic combined corpus changes only ideaId to v2-a-NNN/v2-b-NNN using original array ordinal; original IDs and exact raw response SHA are retained in a sidecar. Duplicate/malformed JSON envelopes are not repaired. Non-object candidate values are kept for the accepted schema to reject. The original provider strings remain intact.
All returned candidates then enter one combined call of the accepted V2 analysis pipeline:existing schema, normalizer, canonical evidence, generalized Naturalness, Evidence-Supported Admission V2, BG with unclassified support, Structured SFE, Creative Shape/history, ranking and unchanged preselection. Combined source adapter and Creative Shape batch review see both shards together. No per-shard scoring or diversity boundary is introduced.
Displayed candidate provenance is SEMANTIC_V2 with actual shard/request identity and actual prompt hash. The accepted normalizer's inherited SEMANTIC_V1 label is retained separately as adapterGenerationSource. This metadata is attached after judgment and supplies no score or selection input. Frozen structured source snapshots and receipts are preserved. The common analysis prompt envelope is not another transmitted request; actual transmitted prompt hashes are separately attached to each source record.
Cross-shard reports use existing structural fingerprints, shape hashes/distances and ranking duplicate-risk outputs. Equivalence is reported as structured similarity, never certified semantic duplication; no new dedup gate removes ideas.

PER-CANDIDATE DIAGNOSTICS
Rule consistency maps only existing evidence:source contradiction findings→RULE_INCONSISTENT; existing supported coherence with no detected finding→RULE_CONSISTENT; unresolved→AMBIGUOUS. Every contradiction retains stated rule, beat number, offending source field/text and exact evidence refs. These are deterministic source-plan inferences, not complete semantic proof or observed pixels.
Opening audits retain existing opening score plus character, goal, object, problem, impossible relation, motion and prior-context evidence. Null means not established; it is never replaced with a convenient no. The existing opening floor60 is unchanged.
Payoff audits retain presence, canonical rule linkage/state change and any final-beat rule findings. New-rule-in-payoff is reported when an existing coherence finding flags a final-beat changed behavior; no finding is not proof of absence. The existing full findings remain available.
Human review uses the accepted policy:production-admissible, ranking-eligible, SFE PASS, admitted with one remaining gate, or unclassified strong core evidence. Novelty is unverified; cards contain no KEEP/KILL or canonical promotion.

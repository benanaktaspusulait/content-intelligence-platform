# Meta Integration Readiness

## Audit scope and evidence

This report audits the current repository/runtime evidence for the approved Meta scope:
Facebook Page publishing/read analytics/comments/replies, Instagram Professional Account/Reels publishing/read analytics/comments/replies, and Meta webhooks. Instagram DM, Messenger, private conversations, unsolicited outbound messaging, and automatic AI reply sending are excluded.

Evidence sources were repository code, tests, compiled migration/test artifacts, Git history, Docker Compose configuration, and the local runbook. No live Meta Graph call, staging deployment record, production deployment record, or shared-database `flyway_schema_history` export was found. Existing uncommitted work was preserved; Family calibration work was not modified.

Status vocabulary used below:

- `IMPLEMENTED` — application behavior exists, with local evidence, but may still require provider/live release evidence.
- `TESTED_LOCAL` — meaningful local/mock/contract evidence exists; provider behavior is not live-verified.
- `BLOCKED_EXTERNAL` — application work is present or prepared, but Meta permissions, App Review, credentials, test account, or deployment evidence is missing.
- `NOT_IMPLEMENTED` — an application-side capability is absent.
- `REQUIRES_REVIEW` — repository evidence is contradictory or insufficient for a safe production claim.

## V21/V22 migration evidence

Repository evidence shows:

- `e9493ac` is the current `HEAD`/`origin/master` checkpoint and contains the intermediate V21 variant that admitted `RECONCILIATION_REQUIRED` directly in V21.
- The current working tree restores V21 to the original immutable constraints and adds `V22__extend_meta_comment_delivery_states.sql`.
- Local Testcontainers reports and compiled artifacts prove only that a disposable database can apply V21 then V22. They do not prove persistence outside that test.
- `docker-compose.yml` declares a persistent local volume named `postgres-data`, and `docker volume ls` showed `intelligence_postgres-data`; however the Docker CLI was unavailable for this audit, so the volume’s Flyway history could not be queried.
- The runbook says the render database was at Flyway 11, which conflicts with the current source/compiled artifacts and is not sufficient evidence of the actual local volume state.
- No repository deployment manifests, Flyway history dump, shared-development/staging/production connection record, or release log was found.

**Migration status: `REQUIRES_REVIEW`.** There is no evidence in the repository that the intermediate V21 was applied to shared development, staging, or production. There is also no sufficient evidence to prove the local persistent `intelligence_postgres-data` volume never applied it. Do not run `flyway repair` automatically. Before rollout, inspect the local/shared environment’s `flyway_schema_history` and record the V21 checksum. If the intermediate checksum is present, use the project-approved Flyway procedure for an already-applied migration; if only the original V21 checksum is present, ship immutable V21 plus V22. The source tree must retain V21 unchanged and V22 as the only delivery-state extension.

## Required application-side completion plan

1. Establish one durable Meta connection owner and encrypted token/account model shared by read and controlled write paths. Persist owner, user/Page/Instagram identities, scopes/capabilities, issued/expiry/refresh/revoke state, validation timestamps, and provider error state.
2. Verify current official Meta permissions/App Review requirements, then add capability discovery and fail-closed capability admission without adding comment/publish scopes to the read-only analytics flow.
3. Discover managed Pages and linked Instagram Professional Accounts after OAuth; persist canonical target identities and eliminate manual IDs as the normal path.
4. Add provider-neutral read ports/adapters for account metadata, Facebook/Instagram publication analytics, comments, replies, pagination, and available deletion/hidden state. Preserve provider-specific provenance and null/partial semantics.
5. Add durable poll cursors and bounded Facebook/Instagram comment/reply polling. Make webhook and polling ingestion share provider-event identity, ordering safeguards, and idempotent upserts.
6. Add provider-side delivery reconciliation for known reply IDs and ambiguous parent-comment child replies. Never blind retry an uncertain write.
7. Add comment/reply GET/list/audit APIs and the Angular connection, capability, review, approval, send-status, reconciliation, and operations surfaces. Add frontend gateway routing for render-owned comment/webhook APIs.
8. Make Meta operational status explicit: kill switches, token health, missing permissions, webhook health, polling lag, provider failures, reply backlog, reconciliation count, and publication queue.
9. Add mock Graph contract tests, migration/history tests, webhook raw-byte/deduplication variants, concurrency/reconciliation tests, frontend tests/build, and an opt-in read-only smoke harness. Keep live writes disabled by default and do not run live publish/reply without explicit approval/test accounts.

## Current readiness summary

- Substantial local implementation exists for Instagram read analytics, basic Meta connection, fail-closed publication/reply controls, signed comment webhooks, local comment persistence, moderation transitions, and provider-independent reply delivery.
- Application-side `NOT_IMPLEMENTED` items remain for durable canonical OAuth, capability admission, account discovery, Facebook analytics, comment reads/polling, inbound replay, delivery reconciliation, review UI, Meta operations health, and full provider contract coverage.
- External `BLOCKED_EXTERNAL` items remain for Meta App Review/Advanced Access, real credentials, dedicated test Page/Instagram Professional Account, and live read/write validation.
- Production write switches remain false by default. No live Meta write was run.

**Overall result: NOT PRODUCTION READY.** The implementation is a partial foundation, not the requested end-to-end integration.

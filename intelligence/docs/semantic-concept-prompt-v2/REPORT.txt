SEMANTIC CONCEPT PROMPT V2 — IMPLEMENTATION AND CONTROLLED EXPERIMENT

Prompt V1, response schema, adapter, canonical evidence, SFE, Naturalness/Admission V2, BG, ranking, shape, history and preselection are unchanged. Six additive prompt/experiment/CLI/test/fixture files select the accepted pipeline explicitly. No new validator or scoring dimension is introduced.

PROMPT DESIGN
One immutable trigger/response rule across all4–5 beats and payoff; private per-beat editing before response; paused frame-zero task/object/problem evidence; direct function-based object relationship; silent visual causality and rule-derived payoff; diverse progression without arbitrary extra powers; simple one-character/one-location production staging. Self-check claims, rationale and suggested payoff family carry no scoring authority.
Exact system and user prompt: exact-prompt-v2.txt and exact-prompt-v2.json. Actual transmitted request is recorded separately in the immutable live experiment, including the existing provider JSON-mode schema suffix.

VERSION AND SAFETY
semanticConceptPromptVersion=v2; promptVersion=semantic-concept-prompt-v2. Existing V1 defaults/API are untouched; PromptV2Request is an additive subtype. SemanticIdea schema remains exactly unchanged. ruleConsistencyStatement is deliberately omitted: no self-certification is needed. dialogueNeed uses the existing NONE/OPTIONAL/REQUIRED enum; silent ideation is requested.
Canonical source, score and source-adapter provenance remain distinct. The accepted normalizer retains its SEMANTIC_V1 generationSource label and sem1 candidate IDs. Actual prompt version is stored separately on every record; the inherited adapter label is explicitly disclosed rather than misreported as a V1 request.

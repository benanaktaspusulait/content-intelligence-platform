======================================================================
GOAL
======================================================================

Create:

SEMANTIC CONCEPT PROMPT V2

for production-aware ~15-second Pompom Hills concept ideation.

V1 proved that semantic generation can explore outside the deterministic grammar.

However, the first live run exposed recurring creative failures:

1. opening premise not visible enough at frame zero
2. impossible rule mutates between beats
3. later beats introduce new behavior not implied by the original rule
4. payoff exists but does not always derive cleanly from the rule
5. concept novelty sometimes comes from arbitrary rule changes rather than causal escalation
6. some concepts require motion/context before the viewer understands the problem
7. strong SFE ideas can still fail Premise Admission because source beats contradict the stated rule

Prompt V2 must address these generation failures directly.

======================================================================
1. CORE PRINCIPLE
======================================================================

The model generates possibilities.

The deterministic system judges them.

The semantic model must NOT:

- rank concepts
- assign scores
- choose winners
- predict virality
- declare production readiness
- bypass validators

It should output raw structured concepts only.

======================================================================
2. PRIMARY CREATIVE TARGET
======================================================================

Generate concepts for approximately:

15-second Pompom Hills shorts.

Each concept should normally contain:

- exactly one main protagonist
- one primary everyday object
- one concrete everyday goal
- one dominant impossible physical/comedic rule
- immediate visible trouble
- 4–5 major causal beats
- escalating consequences from the SAME RULE
- a strong visual payoff
- minimal or zero dialogue

======================================================================
3. MOST IMPORTANT V2 RULE: RULE IMMUTABILITY
======================================================================

Once the impossible rule is established:

IT MUST NEVER CHANGE.

Every later beat must be a logical consequence of the exact same rule.

Do NOT introduce:

- a second magic rule
- a new unexplained behavior
- a new power
- a different trigger
- a special exception
- a final-beat rule mutation

Critical instruction to model:

"Once the impossible rule is established, every beat must obey exactly that same physical rule. Escalation must come from strategy, magnitude, position, accumulation, consequence, or new information — never from changing the rule."

======================================================================
4. RULE CONSISTENCY CHECK INSIDE GENERATION
======================================================================

Before returning each candidate, internally verify:

For Beat 1:
does it follow the rule?

For Beat 2:
does it follow the exact same rule?

For Beat 3:
same?

For Beat 4:
same?

For Beat 5 if present:
same?

If any beat requires a new behavior not implied by the rule:

discard that candidate before output.

Do not expose self-score.

Just return better candidates.

======================================================================
5. FRAME-ZERO STANDARD
======================================================================

The opening still frame is a hard creative requirement.

The first frame should ideally communicate:

CHARACTER
+
EVERYDAY GOAL
+
PRIMARY OBJECT
+
VISIBLE PROBLEM

without requiring:

- dialogue
- text
- prior context
- waiting for movement
- knowing the title
- explanation

Critical instruction:

"The concept must be understandable from a paused frame at the beginning. The viewer should already see what the character wants and what impossible problem is interfering."

======================================================================
6. MOTION-DEPENDENT OPENINGS
======================================================================

Avoid concepts where the impossible rule only becomes apparent after:

- pressing a button
- opening a door
- waiting for a delayed effect
- moving through a room
- completing a first normal action

unless frame zero can already visually show the impossible consequence.

Do not spend the first 2–3 seconds setting up a normal world.

======================================================================
7. EVERYDAY GOAL
======================================================================

The goal must be:

simple
credible
visible
immediately understandable

Examples of goal types:

- brush hair
- put on shoe
- open drawer
- sweep floor
- paint wall
- put object away
- close container
- dry table
- sit down
- carry item
- turn something on/off

Do NOT copy these examples mechanically.

The goal must be physically visible in frame zero.

======================================================================
8. WHY THIS EXACT OBJECT
======================================================================

Every concept must answer:

WHY THIS OBJECT?

The impossible rule should exploit or contradict:

- normal function
- expected motion
- affordance
- material/property
- normal result
- physical relationship to the goal

Avoid:

random object + random magic.

Good conceptual standard:

"This exact object behaves in the worst possible way for what the character is trying to do."

======================================================================
9. STRANGE BUT INTUITIVE
======================================================================

Target:

STRANGE BUT INTUITIVE.

The viewer should think:

"I immediately understand the problem."

and then:

"I did not expect that."

Avoid:

"I don't understand what the rule is."

Novelty must come from:

unexpected logic

not:

randomness.

======================================================================
10. ONE DOMINANT RULE
======================================================================

Each candidate must express the rule in ONE precise sentence.

Example structure:

"Whenever X happens, Y always happens."

or equivalent.

The rule must be:

- observable
- repeatable
- causally stable
- visually understandable

Avoid vague rules such as:

"the object behaves strangely."

======================================================================
11. TRIGGER MUST BE STABLE
======================================================================

The visible trigger must remain consistent.

If rule is triggered by:

touch

then later beats must not suddenly trigger it by:

distance
sound
release
time

unless the original rule explicitly includes that behavior.

Do not mutate trigger logic for convenience.

======================================================================
12. BEAT DESIGN
======================================================================

Return exactly:

4 or 5 major beats.

Each beat must contain:

STRATEGY / ACTION

VISIBLE CONSEQUENCE

NEW INFORMATION OR STATE CHANGE

A beat should not exist merely because the character moves again.

======================================================================
13. STRATEGY ESCALATION
======================================================================

Progression should come from different responses to the same problem.

Possible progression sources:

- new strategy
- new position
- increased magnitude
- environmental use
- changed leverage
- changed timing
- accumulation
- discovery
- consequence spread
- loss of control

Do not default to:

attempt
→ try harder
→ use two hands
→ brace
→ fake success

That pattern has already been overused.

======================================================================
14. SAME ATTEMPT DOES NOT COUNT
======================================================================

Repeated attempts count as separate beats only when at least one materially changes:

- strategy
- physical consequence
- information
- position
- control state
- goal distance
- stakes

Different wording is not different progression.

======================================================================
15. ESCALATION MUST COME FROM THE RULE
======================================================================

Do not add unrelated events merely to make the story bigger.

Bad:

hairbrush tangles hair
then flies
then changes color
then duplicates

unless all of these are unavoidable consequences of one clearly stated rule.

Better:

one rule progressively creates a larger and more difficult consequence.

======================================================================
16. PAYOFF MUST BE RULE-DERIVED
======================================================================

The final payoff must be a logical consequence of the SAME impossible rule.

Before returning a candidate ask internally:

"Could this payoff happen if the original rule were removed?"

If YES:

the payoff is probably unrelated.

Discard or redesign.

======================================================================
17. PAYOFF VARIETY
======================================================================

Do not default to:

temporary success
→ original problem comes back.

Encourage:

- role reversal
- control transfer
- property transfer
- absurd success
- solution creates new problem
- environmental takeover
- logical extreme
- chain reaction
- reveal
- goal achieved in the wrong way
- character becomes part of the object state
- object succeeds while character fails

But the payoff must obey the original rule.

======================================================================
18. AVOID RANDOM PAYOFF TWISTS
======================================================================

Do NOT create a surprise merely by introducing:

a new object
a new character
a new magic effect
a different rule
an unexplained external force

The payoff should feel surprising in outcome but inevitable in retrospect.

======================================================================
19. PAYOFF VISUALITY
======================================================================

The payoff should be understandable visually.

Avoid endings that rely mainly on:

dialogue
text
explanation
internal realization

Prefer physical visual state change.

======================================================================
20. SILENT-VIEW LEGIBILITY
======================================================================

Assume viewer watches with no sound.

The full story should remain understandable.

Dialogue need should normally be:

NONE
or
MINIMAL

Do not use dialogue to explain:

goal
rule
trigger
payoff

======================================================================
21. PRODUCTION FEASIBILITY
======================================================================

Prefer concepts suitable for AI video generation:

- one character
- one main object
- one location
- broad body actions
- stable object identity
- visually clear poses
- limited moving elements

Avoid concepts requiring:

- tiny text
- many small objects
- complex hand manipulation
- many characters
- crowds
- fine mechanical transformations
- rapid location changes
- invisible forces that cannot be staged clearly

shrink
adhesion

stable
object-specific
visually legible
rule-consistent

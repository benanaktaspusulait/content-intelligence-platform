# Creative Optimization V2 — model-authored production contract

Implementation readiness from controlled structured mock responses. **Real-model creative effectiveness remains UNVERIFIED.** No paid inference occurred; actual provider cost is $0. The previous one-call authorization was already consumed and was not reused.

## 1. Why the real model was limited

The historical `Intervention` wire schema allowed only opportunityId, operation, layout, camera and rationale. It had no choreography or state-presentation fields. `_instructions()` expanded those small selections into server-authored prose and the compiler injected `locked-off medium shot`. The first real result therefore demonstrated strategy selection, not independent reconstruction. Its saved response still recompiles to exactly its original candidate bytes.

## 2. Architecture changes within existing V2

Generation contract remains `creative-reconstruction-v2`; future official requests carry `optimizationGenerationInstructionsVersion=model-authored-production-v1`. The existing provider adapter, reservation, fingerprint, persistence, recovery and comparison flow remain in use. The new instructions version changes future request identity. Cached template comparisons cannot satisfy a new authored-generation request. Recovery retains the original version, including absence of an instructions version.

The new structured `production` object contains source-bound spatialRelationships, choreography/action and consequence, stateProgression, temporalPresentation, cameraComposition and generatorConstraints. SourceReferenceCatalog supplies exact quotes and code-point spans from the current input, with typed ENTITY/ACTION/CONSEQUENCE/STATE references. It supplies no improved full prompt.

For MODEL_AUTHORED, the compiler validates these fields, substitutes exact source references, and joins the author's instructions. It does not call the template generator or force a medium shot. BOUNDED_TEMPLATE_FALLBACK is explicit, requires a justification, and is attributed SERVER_TEMPLATE. Invalid authoring is rejected rather than silently converted to a template. Multiple relevant beats may change; unchanged events remain exact source text.

Existing source preservation, canonical evaluation, local critic and production risk checks still run. For the new authored contract a critic REWRITE/BLOCKED/FAIL keeps approval eligibility closed. This is an execution-risk gate, not a score or canonical-outcome change. No new framework, scoring feature or infrastructure service was added.

## 3. What the model can now author

The model can write an original diagonal reach path, cabinet/finger depth relationship, sticky-edge visibility instructions, a wide locked composition, distinct arrangements for each source count, transitions and generator constraints. It can address opening contact and escalation in one candidate. Server templates no longer determine those words. Controlled counterfactual responses with different choreography compile to different prompts and preserve their exact authored instructions; this proves input responsiveness, not autonomous creativity.

## 7. Remaining limitations

Materiality recognition is conservative deterministic geometry/state validation; it is not general creative judgment. The supported safe operation grammar is still CONTACT_PLANE, SEPARATE_ACTION_RESULT and COUNTABLE_STATE_PATH. LOCKED camera remains the safe contact/count continuity policy. New story events/attempts, new props and revised endings are outside this task. Free-form prose can express subtle semantic contradictions that these checks cannot fully prove absent; independent semantic and visual review remain necessary. Source count extraction currently relies on the existing parser's explicit progression syntax. Current window feasibility, accurate note counts, contact fidelity and viewer benefit require actual evidence. The mock was deliberately authored by test code; no autonomous creativity is claimed.

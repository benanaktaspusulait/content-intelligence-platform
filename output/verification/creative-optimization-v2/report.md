This status means meaningful source-bound production reconstruction has been demonstrated through the real built frontend/backend/ML pipeline using a mocked provider and disposable PostgreSQL. It does not mean rendered or audience superiority, live-provider capability verification, or operator approval.

The authored response fixtures and prior full-stack mock run establish recognition, compilation and integration; they are **not evidence that a real optimizer generated an improvement**. Separate input-responsive reconstruction tests now build fresh structured plans from runtime diagnosis and objectives without a prepared answer, and test objective/source counterfactuals and no-candidate behavior. No real provider test has been authorized or run.

## 1. Root causes of weak generation

The old plan-first schema allowed catalog selection plus camera framing/motion and explanation. Its compiler principally added “visible together”, “focus then”, or count holds to otherwise unchanged execution. The legacy distinctness evaluator compared timing/framing/motion signatures; comparison could regard motion or framing+timing as material. There was no precise diagnosis-to-spatial-choreography change contract. Backend, comparison and frontend also required exactly two candidates. Model capability itself was not established by these code findings.

Concrete function-level evidence is in `root-cause-audit.md`; no historical scorer was changed.

Existing PROMPT_OPTIMIZATION dispatch, plan-first protected_contract, profile ownership, source-bound Video Plan IR/parser, source-plan endpoint, canonical Ruleset 1.11 review, durable attempt reservation, budget validation, idempotency, response persistence/recovery, comparison lineage, immutable prompt approval, Step 6 governance and F8 remain the application infrastructure. ## 3. Architecture changes

The existing role selects the versioned `creative-reconstruction-v2` strategy. `creative_reconstruction.py` implements source diagnosis, protected/editable layers, structured reconstruction, bounded critique, server-owned prompt compilation and comparative proof. Legacy contracts remain available for historical recovery/comparison; recovery preserves the original contract instead of silently interpreting old provider evidence as V2.

`creative-quality-v2.json` governs the qualitative evidence model and its six dimensions. Its version/dimensions are checked when diagnosing. Protected identity, premise, events/order, physical rule, outcomes, ending and safety are separated from editable spatial staging, choreography, composition, continuity and presentation. Missing independent semantic evidence remains UNKNOWN. Requests requiring protected-story changes return STORY_CHANGE_REQUIRES_APPROVAL.

Zero, one or two candidates are supported end to end. No defensible plan yields NO_JUSTIFIED_IMPROVEMENT / KEEP_ORIGINAL. No candidate is automatically selected or approved.

## 4. Creative diagnosis

Each opportunity includes the exact source quote/span, beat/time window, current instruction, specific uncertainty, proposed intervention, expected observable change, viewing hypothesis, production risk and evidence classification. Canonical FAIL is neither necessary nor sufficient for a rewrite.

Mimi's source supplies three grounded operation families: intended/actual contact visibility, separation action/result choreography, and countable multiplication progression. Opening strategy is honored: CURIOSITY_DISCOVERY does not force complete frame-zero causal revelation. Ending review does not universally require comedy, closure or a loop.

## 5. Production reconstruction

The provider proposes an objective and selects source-grounded production operations plus spatial layout and camera discipline. The compiler produces a complete production prompt, preserving narrative/event bytes and replacing the editable execution layer with specific staging instructions. This permits a same-camera physical correction to be meaningful and does not define materiality using textual similarity.

Current supported operations are CONTACT_PLANE, SEPARATE_ACTION_RESULT and COUNTABLE_STATE_PATH. This is a bounded source-grounded grammar, not unrestricted narrative rewriting. Unsupported source evidence fails closed rather than inventing a visual relationship.

## 6. Critique and bounded revision

The critic checks diagnosed opportunity binding, spatial/choreographic difference, duplicates, source scope, story-change requests, moving-contact-view risk and unsupported audience/render claims. Camera labels, unchanged layouts and timestamp-only substitutions are rejected. One revision may be included in the **same original provider response**, targeting the same opportunity and candidate; the server returns actionable critique reasons and accepts at most that bounded correction. There is no extra provider call, automatic retry or endless loop.

Canonical/source evaluation then provides a second check. A canonical or deterministic production-risk regression disables approval and exposes the exact changed findings. Any later paid revision requires fresh explicit operator consent and bounded budget.

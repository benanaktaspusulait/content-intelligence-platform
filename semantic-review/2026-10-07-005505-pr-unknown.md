# Luca Sticky Ball canonical evidence and quality-report export audit

The current Luca path fixes the original report contradictions: the fixture produces seven raw beats with six canonical load beats, two active attempts (`PULL` and intended `SQUEEZE`), separate reactive `CATCH` evidence, six deduplicated state transitions, and canonical attempt confidence `0.95`. Medium inferred `STUBBORN_RETURN_LOOP` evidence does not activate the specialized hook exception, the PDF keeps percent/outcome presentation distinct, and no historical performance data enters the quality path. The remaining risks are at integration boundaries: arbitrary pre-populated strategy fields are trusted, one escalation failure branch retains a raw dataclass, auto-fix drops canonical confidence, and legacy stored DTO snapshots are not normalized. Watch for: **Important (confirmed)** strategy-family contamination and legacy-report null lists can change scoring or break the stored-report UI; **Important (confirmed)** canonical evidence is not uniformly JSON-safe and auto-fix does not propagate `0.95`.

**Verdict**: NEEDS_CHANGES

## High-level view

The parser and canonical evidence layer distinguish Luca’s reactive `CATCH` from intended `SQUEEZE`; the escalation beat stays outside the active-attempt count while preserving wall-flex/resistance evidence. The remaining canonical-layer issue is that `strategy_semantics_for_beat` accepts arbitrary pre-existing family fields, while the escalation rule serializes typed evidence inconsistently on FAIL.

Story-density and ruleset gates use six major/load beats, keep Luca’s single-generation plan manageable, and leave the medium return-loop candidate inactive. Evaluated subsets retain family scores while no-evidence families remain null; timeline state shares stay in the 0–100 percent unit exactly once and the PDF exposes all five outcome categories. No quality-path code reads historical performance observations, and the 1.5/1.6/1.7 ruleset files have no working-tree diff.

The normal `/validate` path carries canonical confidence through assessment, API response, `QualityReportDto`, and PDF. The `/auto-fix` path omits the final IR when converting its report, and restored pre-change `QualityReportDto` snapshots bypass the overloaded compatibility constructor, leaving nullable collections that the frontend dereferences.

### Important — Strategy-family provenance *(confirmed)*

`intelligence/ml-service/app/quality/canonical_evidence.py:89-114` line 96 prefers `beat["intendedStrategyFamily"]` and then `beat["strategyFamily"]` verbatim before falling back to the normalized action. `strategy_family_for_beat` returns that value directly. A direct probe with `primaryVerb="PULL"`, `targetObject="red ball"`, and `strategyFamily="red ball"` returns `"red ball"`; `intendedStrategyFamily="restore_or_control_normal_object_use"` is likewise returned verbatim. The parser-generated Luca fixture avoids this because it writes normalized fields first, so the current golden tests pass, but persisted/legacy/upstream IR can inflate `distinct_strategy_count` with object/effect labels and violates the requirement that those fields never become strategy families.

### Important — Typed escalation evidence is not uniformly JSON-safe *(confirmed)*

`CanonicalEscalationEvidence` is a frozen dataclass with `to_dict()` at `intelligence/ml-service/app/quality/canonical_evidence.py:210-244`. `intelligence/ml-service/app/rules/rule_engine.py:_evaluate_escalation_005` uses `evidence_payload` for UNKNOWN and PASS, then puts the raw `evidence` object in `details` on the FAIL branch at approximately lines 2462-2471. `json.dumps(result.details)` raises `TypeError: Object of type CanonicalEscalationEvidence is not JSON serializable`. FastAPI/Pydantic currently encodes this dataclass, but generic report serialization, logging, or another consumer of `RuleEvaluation.details` is not guaranteed to. The wall-flex/resistance fields are preserved; the issue is the inconsistent boundary representation.

### Important — Canonical confidence is lost on auto-fix *(confirmed)*

`intelligence/ml-service/app/api/quality.py:369` passes the parsed IR to `convert_quality_report`, and `convert_quality_report` reads canonical confidence from the assessment at approximately lines 648-670; this is why direct Luca conversion and the PDF test see `0.95` separately from parser confidence. In contrast, `auto_fix_prompt` calls `convert_quality_report(result.final_enhanced_report, ruleset_version)` at approximately line 448 without an IR. `AutoFixResult` in `intelligence/ml-service/app/autofix/iteration_loop.py:36-44` stores the final prompt and reports but no final IR. The final auto-fix API report therefore rebuilds its assessment from `{}` and returns `canonical_evidence_confidence: null`, even when its final prompt contains the same canonical attempts.

### Important — Legacy `QualityReportDto` snapshots bypass compatibility defaults *(confirmed)*

The new record shape in `intelligence/backend/src/main/java/com/pompomhills/intelligence/quality/QualityReportDto.java:36-64` adds outcome lists, parser metadata, assessments, and canonical confidence. Its overloaded constructor at approximately lines 68-127 supplies empty collections only when Java code calls that overload; Jackson does not use it when reading a stored JSON snapshot. `QualityReportSnapshots.fromJson` at `intelligence/backend/src/main/java/com/pompomhills/intelligence/quality/QualityReportSnapshots.java:39-47` deserializes directly into the canonical record, so old snapshots produce null `serviceErrors`, `unknownRules`, `notApplicableRules`, `evidenceMissing`, and parser metadata fields. `QualityValidationHistoryService.findLatest` returns that object unchanged at approximately lines 39-46. The stored-report frontend then dereferences `report.serviceErrors.length`, `report.unknownRules.length`, and `report.notApplicableRules.length` in `intelligence/frontend/src/app/pages/quality-validator/quality-validator.component.html:214-221`, and `report.evidenceMissing.length`/`report.parserWarnings.length` at lines 237-238. Pre-change snapshots also contain the old boolean `result` field rather than the new `outcome`, which the new DTO silently leaves null. This is a real backward-compatibility gap even though `QualityReportDtoTest` only deserializes a complete new snake-case payload.

### Minor — Negative regression coverage *(confirmed)*

The 428-test ML run is green, and the targeted backend `QualityReportPdfServiceTest`/`QualityReportDtoTest` run is green. Existing tests cover Luca’s positive semantics, escalation without active attempts, unsupported goals, medium profile candidates, overloaded temporal plans, mixed PASS/FAIL/UNKNOWN scoring, state-share scaling, and all PDF outcome labels. They do not exercise arbitrary legacy strategy fields, `json.dumps` on escalation FAIL details, auto-fix report conversion, an old stored DTO snapshot, or a **possible** realization negative such as `abnormal` being mistaken for `normal` by the substring check in `story_density_evidence`. The full backend Maven suite was not completed within the 180-second Testcontainers run, so only the targeted Java result is verified here.

## Canonical Family 4 projection and timeout preservation

`extract_dimension_values` in `comparator.py:156-186` sends both baseline and current snapshots through the same `mechanic_payoff_evidence` call when `videoPlanIR` is present. `CENTRAL_MECHANIC` uses `mechanic_family`, while interaction, fake resolution, recurrence, payoff, and same-rule relation use the typed canonical fields; serialized `dimensionValues` are consulted only when a projected value is `None`. The early no-IR return preserves stored parser-timeout values rather than fabricating `NOT_ESTABLISHED` evidence.

## Recurrence is incorrectly dependent on fake resolution

**Confirmed:** `mechanic_payoff_evidence` computes recurrence as `fake and (...)` (`canonical_evidence.py:502-503`). An established mechanic that returns or reasserts without a detected fake-resolution beat is therefore reported as `NOT_ESTABLISHED`, even though the Family 4 contract defines recurrence as the established mechanic returning after the apparent state, not as a property that requires `FAKE_RESOLUTION == PRESENT`. The focused tests only assert recurrence in examples that also contain a fake resolution, so this boundary is not protected. Recurrence detection should be based on established-mechanic recurrence evidence independently, with a regression test for a returning mechanic without a fake-resolution marker.

## Quantity-family payoff can bless an unrelated twist

**Confirmed:** the `QUANTITY_MULTIPLICATION` same-rule branch returns true when `final_payoff.type` is `escalation`, `twist`, or `payoff`, even when the final beat and payoff description contain no quantity-mechanic evidence (`canonical_evidence.py:508-509`). That makes an unrelated narrative/final twist appear as `SAME_RULE`; the same payoff-type fallback also makes recurrence true when fake resolution is present. The existing unrelated-twist test in `test_family4_mechanic_payoff.py:58-69` exercises the generic rope branch and therefore does not cover this family-specific fallback. Same-rule and recurrence should require evidence tying the final consequence to the established mechanic, and the test corpus should include an unrelated quantity-family twist.

## Frozen Gold Truth does not match the generated JSON

**Confirmed:** the completion report’s Gold Truth table labels Box Cat `STUBBORN_RETURN_ANIMAL_CLAIM` and Island Journal payoff `NOT_ESTABLISHED` (`FAMILY_4_CALIBRATION_REPORT.md:33,36`), but the generated JSON expects `STUBBORN_RETURN_LOOP` for Box Cat (`golden-regression-report.json:2035-2037`) and `MODERATE` for Island Journal payoff (`golden-regression-report.json:3335-3338`). The rows are classified as an unchanged known issue and Gold Review Required rather than new regressions, so the `PASS` gate does not prove the documented frozen truth was evaluated. The labels and generated report must be synchronized before calling the calibration frozen.

# Lossless Family 9 report and UI representation consistency

This change carries the ML report’s nullable score, creative grade, aggregation facts, evidence completeness, and render authorization into the Family 9 assessment/API representation, PDF, frontend, and Golden checks. The exact-score edit is confined to the assessment projection; the rule engine and scorer still own the canonical score. The PDF and frontend expose the three orthogonal axes and keep ratio coverage separate from the legacy integer percentage. Watch for: **confirmed Critical** nested representation omissions can pass the Golden consistency check, **confirmed Important** frontend fallbacks can relabel a legacy grade as creative grade or crash on an older stored report, and **confirmed Important** the database summary column still rounds exact scores to two decimals.

**Spec verdict**: NEEDS_CHANGES. **Quality verdict**: targeted Family 9 tests pass, but the release-gate and storage gaps prevent a freeze; the broader frontend failures are unrelated to this scope.

**Findings**: 1 Critical, 2 Important, 0 Minor.

**Verdict**: NEEDS_CHANGES

## High-level view

The ML/API path preserves nullable scores and the JSON snapshot retains them; the remaining **confirmed** storage asymmetry is that `quality_validations.overall_score` remains `NUMERIC(5,2)` while the exact JSON projection can carry more precision.

The PDF prints Creative Quality, Evidence Completeness, and Render Authorization separately, includes the aggregation counts and authorization reason fields, and converts the known ratio exactly once. The frontend has the same orthogonal Family 8 display and null score formatter, but its header still falls back from `creative_grade` to legacy `grade` and assumes legacy readiness fields exist (**confirmed**).

Representation mismatches are counted independently in the cohort report and fail the CI gate, while the nine-asset manifest and parser-timeout not-evaluated contract remain unchanged. The comparator’s top-level presence checks are useful, but its nested source comparison drops missing values before comparing them, leaving a lossless projection omission invisible (**confirmed**).

1. **Critical — Nested projection omission bypasses the Golden gate (confirmed)** — `_compare_representation_sources` filters out missing paths, so an API report can omit authorization reasons, aggregation fields, family scores, or another nested projection and still be reported consistent. Compare required source presence as well as values, then add missing-nested-field fixtures and assert `representationMismatches` fails the gate.
2. **Important — Legacy fallback masks null creative grade and is not safe for old reports (confirmed)** — The frontend labels `creative_grade || grade` as “Creative grade,” and an empty Java `preRenderAssessment` map can reach a template expression that calls `replaceAll` on undefined readiness. Render canonical null as `N/A`, keep legacy readiness explicitly separate, and guard absent/legacy assessment fields.
3. **Important — Exact score is lost in the persisted summary column (confirmed)** — The new ML projection preserves values such as `82.567`, but the existing `overall_score NUMERIC(5,2)` column rounds that value while the JSON snapshot retains it; the quality-summary query reads the rounded column. Increase the column scale or explicitly make the JSON snapshot the only exact score source and test the chosen contract.

### Exact score, nullability, and persistence boundaries

The current ML change is representation-only: `build_pre_render_assessment` now forwards `report.overall_score` directly to both `creative_score` and `family8.creativeQuality.creativeScore`; no rule, parser, scorer, family weighting, status, or threshold code changed. `QualityReportResponse`, `ScoreCardDto`, `QualityReportDto`, the entity, and the snapshot path all accept nullable scores, and the focused tests preserve null rather than converting it to zero. V45 correctly drops the legacy `NOT NULL` constraint without weakening the 0–100 check.

The remaining storage asymmetry is **confirmed**. The original `quality_validations.overall_score NUMERIC(5,2)` schema persists only two decimal places, whereas `report_json` serializes the full `Double`. The linked and standalone services write both representations, and `ContentWorkspaceController` uses the summary column for the persisted quality-card score. This does not change render authorization decisions, which use the ML DTO before persistence, but it violates an end-to-end lossless score contract for values with more than two decimals.

### Separate axes, coverage units, and authorization reasons

`QualityReportPdfService` renders the three Family 8 axes as separate labeled lines. It prints `NOT EVALUATED` alongside the other aggregation counts, shows null score/family values as visible placeholders, treats `evaluationCoverage` as a ratio, and emits authorization code, source, message, and references. The frontend uses the explicit `RATIO`/`PERCENT` formatter, shows all aggregation counts including `notEvaluatedCount`, and displays the canonical authorization status and reason references independently from the compatibility readiness field. The focused backend PDF/DTO tests and frontend Family 9 formatter spec cover these paths.

The frontend summary still has a **confirmed** representation problem at `quality-validator.component.html`: `creative_grade || grade` turns a missing creative grade into a legacy grade while labeling it as creative quality, and `prompt_stage?.replaceAll(...) || readiness.replaceAll(...)` has no safe fallback for an old stored report. `QualityReportDto` deliberately normalizes an absent `preRenderAssessment` to an empty map for backward compatibility, so `*ngIf="report.preRenderAssessment"` does not protect this expression. The existing Family 9 frontend spec tests helper functions rather than rendering this report template, which is why this case is uncovered.

### Nested Golden representation consistency and independent gating

The Golden report carries `representationMismatches` through `compare_cohort`, `build_regression_report`, and `evaluate_ci_gate`; any counted mismatch independently produces `FAIL`. The deterministic runner keeps parser timeouts out of creative representation comparison and produces a null-score, zero-scored, positive-`notEvaluatedCount` aggregation. The nine-asset test exercises every manifest asset, and no Golden manifest, truth, baseline, parser, scorer, or ruleset file changed in the reviewed Family 9 diff.

The comparator’s **confirmed** gap is in the common source helper: it constructs `available` by removing every `_MISSING` value and returns immediately when fewer than two values remain. A direct probe deleting `apiReport.pre_render_assessment.family8.renderAuthorization.reasons` from the coherent fixture returned `checked: true, consistent: true, mismatches: []`. The same blind spot applies to missing nested aggregation counts and family-score projections. Since the cohort counter only sees the helper’s mismatch list, this can produce a false PASS at the exact gate intended to protect lossless transport.

### Verification and scope

Focused validation passed: 36 ML/Golden pytest cases, the backend `QualityReportDtoTest` and `QualityReportPdfServiceTest` Maven suite, and the Angular Family 9 spec (3 tests). The frontend production build passed with existing bundle-budget warnings. The full frontend suite still has nine failures in the unrelated creative-intelligence/video-detail tests; those failures do not excuse the three implementation findings above. The working tree also contains unrelated TikTok publisher changes, which were excluded from this review.
